Какие основные типы памяти существуют в архитектуре CUDA и чем они отличаются по скорости доступа?В архитектуре CUDA выделяют следующие основные типы памяти (Лекция №4):
Глобальная память (global memory) — самая большая по объёму (гигабайты), доступна всем потокам, но самая медленная (высокая латентность ~400–600 циклов).
Разделяемая память (shared memory) — быстрая (латентность ~10–20 циклов), объём ограничен (десятки–сотни КБ на блок), доступна только потокам внутри одного блока.
Локальная память (local memory) — очень быстрая (регистры, ~1 цикл), объём крайне мал (десятки регистров на поток), используется автоматически компилятором для локальных переменных.
Константная память (constant memory) — только для чтения, кэшируется, объём 64 КБ, доступна всем потокам, очень быстрая при одинаковых обращениях.
Текстурная память — оптимизирована для 2D/3D данных, кэшируется, только чтение.
Основное различие по скорости: регистры → shared → constant/texture → global (Лекция №4).
В каких случаях использование разделяемой памяти позволяет ускорить выполнение CUDA-программы?Разделяемая память (shared memory) даёт значительное ускорение в следующих случаях (Лекция №4):
Когда один и тот же элемент данных используется многократно потоками внутри одного блока (пример: редукция, матричные операции, сортировка подмассивов).
При необходимости быстрого обмена данными между потоками одного блока (например, слияние отсортированных подмассивов).
В задачах с повторным доступом к одним и тем же данным (например, в фильтрах, стеках, очередях внутри блока).
Почему ускоряет: shared memory в 10–100 раз быстрее глобальной за счёт низкой латентности и высокой пропускной способности. Она позволяет сначала загрузить данные один раз коалесцированно, а затем работать с ними локально (Лекция №4: минимизация глобальных обращений).
Как шаблон доступа к глобальной памяти влияет на производительность GPU-программы?Шаблон доступа к глобальной памяти напрямую определяет пропускную способность (Лекция №4):
Коалесцированный доступ — все 32 потока варпа читают/пишут в последовательные 128-байтные сегменты памяти → запросы объединяются в один транзакт → максимальная скорость (почти как у регистров).
Некоалесцированный доступ — потоки обращаются к разнесённым адресам → каждый запрос дробится на множество транзактов → латентность и пропускная способность падают в разы (иногда в 10–32 раза).
Пример: последовательный доступ (idx) — быстро; обратный (N-1-idx) или страйд-доступ — медленно (Лекция №4).
Почему одинаковый алгоритм на GPU может показывать разное время выполнения при разных способах обращения к памяти?Потому что производительность GPU сильно ограничена пропускной способностью памяти, а не только вычислениями (Лекция №4):
Глобальная память имеет очень высокую латентность (~400–600 циклов).
При коалесцированном доступе запросы объединяются → GPU может скрывать латентность.
При некоалесцированном доступе каждый поток генерирует отдельный запрос → сотни транзактов вместо одного → простой потоков, низкая загрузка памяти.
Итог: разница в скорости доступа к глобальной памяти может давать ускорение/замедление в 5–30 раз даже при одинаковом количестве операций (Лекция №4).
Как размер блока потоков влияет на производительность CUDA-ядра?Размер блока потоков влияет на несколько ключевых параметров (Лекция №4):
Маленький блок (32–64 потока): низкая загрузка GPU (occupancy), много блоков → overhead на запуск блоков.
Средний блок (128–256 потоков): оптимальный баланс — высокая загрузка, достаточно регистров и shared памяти.
Большой блок (512–1024 потока): может не хватить регистров или shared памяти → снижение occupancy, замедление.
Оптимальный размер: обычно 128–512 потоков (чаще всего 256) — зависит от конкретного GPU и использования ресурсов (Лекция №4).
Что такое варп и почему важно учитывать его при разработке CUDA-программ?Варп (warp) — это группа из 32 потоков, которые выполняются одновременно на одном SM (Streaming Multiprocessor) GPU (Лекция №3 + №4).Почему важно учитывать:
Все 32 потока варпа выполняют одну и ту же инструкцию одновременно (SIMT-модель).
Если в коде есть ветвление (if-else), и потоки внутри варпа идут разными путями → warp divergence → часть потоков простаивает → замедление до 2 раз.
Коалесцированный доступ к памяти возможен только внутри варпа (32 потока должны обращаться к последовательным 128-байтным сегментам).
Вывод: разработчик должен минимизировать расхождения внутри варпа и проектировать доступ к памяти по 32 потока (Лекция №4).
Какие факторы необходимо учитывать при выборе конфигурации сетки и блоков потоков?При выборе конфигурации (размер блока и сетки) необходимо учитывать (Лекция №4):
Occupancy — процент занятых потоков относительно максимального числа (цель — 50–70%+).
Количество регистров на поток — чем больше блок, тем меньше регистров на поток → возможен спад occupancy.
Объём разделяемой памяти — большой блок → больше shared на блок → может не хватить на SM.
Коалесцированный доступ — размер блока должен быть кратным варпу (32) и способствовать последовательному доступу.
Размер задачи — сетка должна покрывать весь массив (N + block_size - 1) / block_size.
Архитектура GPU — разные поколения (Volta, Ampere, Ada) имеют разные лимиты регистров и shared памяти.
Рекомендация: начинать с 128–256 потоков на блок и профилировать с Nsight (Лекция №4).
