## Краткое описание решения и результатов

### Задание 1 — Поэлементное умножение массива на число (task1_elementwise.cu)

Сравниваются две реализации:  
- **Глобальная память** — каждый поток напрямую умножает элемент (медленный доступ)  
- **Разделяемая память** — данные загружаются в shared, обработка происходит быстро, затем запись обратно  


**Вывод:**  
Разделяемая память радикально снижает количество обращений к глобальной памяти и устраняет конфликты — ключевое преимущество для задач с повторным доступом к данным (Лекция №4).

### Задание 2 — Поэлементное сложение двух массивов + влияние размера блока (task2_array_add.cu)

Реализовано сложение двух массивов.  
Проведено тестирование с разными размерами блока: 64, 128, 256, 512 потоков.  

**Вывод:**  
Оптимальный размер блока обычно 256–512 потоков — зависит от архитектуры GPU и баланса occupancy/регистров (Лекция №4).

### Задание 3 — Коалесцированный vs некоалесцированный доступ (task3_coalesced.cu)

Реализовано умножение элементов массива двумя способами:  
- Коалесцированный — последовательный доступ (быстро)  
- Некоалесцированный — обратный порядок (медленно)  

**Вывод:**  
Коалесцированный доступ критически важен для высокой пропускной способности глобальной памяти (Лекция №4).

### Задание 4 — Поиск оптимальной конфигурации блоков (task4_optimal_config.cu)

Реализовано масштабирование массива.  
Протестированы размеры блока: 64, 128, 256, 512.  

**Вывод:**  
Оптимальная конфигурация — 256 потоков на блок (максимальная загрузка GPU без нехватки регистров) — Лекция №4.
