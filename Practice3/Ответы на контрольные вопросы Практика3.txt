В чём основные преимущества GPU перед CPU для параллельных вычислений?
GPU имеет тысячи ядер, оптимизированных для массово-параллельных задач (Лекция №3). В отличие от CPU (несколько мощных ядер), GPU может одновременно выполнять тысячи простых операций — идеально для сортировки больших массивов.
Почему Merge Sort, Quick Sort и Heap Sort лучше подходят для GPU, чем простые O(n²) алгоритмы?
Эти алгоритмы имеют сложность O(n log n) и содержат независимые подзадачи (слияние подмассивов, сравнения в куче), которые можно распределить по тысячам потоков. Простые алгоритмы (пузырьком) имеют больше зависимостей и меньше параллелизма.
Что такое разделяемая память (shared memory) в CUDA и зачем она нужна?
Shared memory — быстрая память внутри блока потоков (Лекция №3). Она в десятки раз быстрее глобальной памяти. Используется для обмена данными между потоками одного блока (например, при слиянии подмассивов).
Как работает индексация потоков в CUDA?
Каждый поток имеет уникальные индексы: threadIdx.x, blockIdx.x, blockDim.x. Глобальный индекс: i = threadIdx.x + blockDim.x * blockIdx.x. Это позволяет каждому потоку обрабатывать свой элемент массива.
Какие основные этапы выполнения программы на CUDA?
Выделение памяти на GPU (cudaMalloc)
Копирование данных с CPU на GPU (cudaMemcpy HostToDevice)
Запуск ядра (kernel<<<blocks, threads>>>())
Синхронизация (cudaDeviceSynchronize)
Копирование результатов обратно
Освобождение памяти (cudaFree)

Почему важно использовать коалесцированный доступ к памяти на GPU?
Потоки в warp (32 потока) читают память одновременно. Коалесцированный доступ (последовательные адреса) позволяет читать одним запросом, иначе — множество медленных обращений к глобальной памяти (Лекция №3).
В чём отличие гетерогенной параллелизации от обычной (на CPU)?
Гетерогенная — использование разных устройств (CPU + GPU). GPU берёт массово-параллельные части, CPU — последовательные и управление (Лекция №1). Позволяет достичь максимальной производительности.
