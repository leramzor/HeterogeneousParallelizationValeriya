## Подробное описание решения каждой части

### Часть 1 (`part1_bitonic_sort.cu`) — Bitonic Merge Sort на GPU

**Что сделано:**
- Полностью параллельная реализация Bitonic Sort (вариант Merge Sort для GPU).
- Массив размером 2¹⁶ = 65 536 элементов (обязательно степень двойки).
- Каждый поток сравнивает пару элементов, используя глобальную индексацию.
- Запуск ядер для всех фаз сортировки.
- Измерено время выполнения только на GPU.

**Как работает:**
- Алгоритм состоит из логарифмического количества фаз, в каждой фазе – сравнения пар по битонной последовательности.
- Использована только глобальная память (для учебной простоты), но принцип массовой параллельности продемонстрирован.

### Часть 2 (`part2_quick_sort_hybrid.cu`) — Гибридная Quick Sort

**Что сделано:**
- Реализован один уровень partition полностью параллельно на GPU (каждый поток определяет, меньше ли его элемент опорного).
- Флаги собираются на CPU, выполняется перестановка.
- Рекурсивная часть Quick Sort выполняется на CPU (стандартная реализация).
- Массив до 1 000 000 элементов.

**Как работает:**
- GPU ускоряет наиболее вычислительно интенсивную часть – сравнение всех элементов с pivot.
- Гибридный подход позволяет обойти проблему рекурсии на GPU.

### Часть 3 (`part3_heap_sort.cu`) — Heap Sort с параллельным heapify

**Что сделано:**
- Параллельное построение кучи: каждый поток выполняет heapify для своего поддерева.
- Последовательное извлечение максимума с параллельным восстановлением кучи.
- Массив до 524 288 элементов.

**Как работает:**
- Основная параллелизация – в операции heapify, которая применяется независимо к разным узлам.
