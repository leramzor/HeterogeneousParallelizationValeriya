## Подробное описание решения каждой части

### Часть 1 (`part1_bubble.cpp`) — Сортировка пузырьком (Bubble Sort)

**Что сделано:**
- Реализована классическая последовательная версия
- Параллельная версия использует метод чётных/нечётных фаз (odd-even transposition)
- Массив из 20 000 элементов, заполнен случайными числами
- Измерено время выполнения и вычислено ускорение

**Как работает:**
// Чётная и нечётная фазы — независимые сравнения, безопасно параллелятся
#pragma omp parallel for
for (int j = 0; j < n-1-phase; j += 2) {
if (arr[j] > arr[j+1]) std::swap(arr[j], arr[j+1]);
} // чётная фаза

#pragma omp parallel for
for (int j = 1; j < n-1-phase; j += 2) {
if (arr[j] > arr[j+1]) std::swap(arr[j], arr[j+1]);
} // нечётная фаза

### Часть 2 (`part2_selection.cpp`) — Сортировка выбором (Selection Sort)

**Что сделано:**
- Последовательная версия с классическим поиском минимума
- Параллельная версия: параллельный поиск минимума в неотсортированной части с `reduction(min:min_idx)`
- Массив из 15 000 элементов
- Измерено время и ускорение

**Как работает:**
// Параллельный поиск минимума — каждый поток обновляет локальный минимум
#pragma omp parallel for reduction(min:min_idx)
for (int j = i+1; j < n; ++j) {
if (arr[j] < arr[min_idx]) min_idx = j;
}

### Часть 3 (`part3_insertion.cpp`) — Сортировка вставками (Insertion Sort)

**Что сделано:**
- Классическая последовательная версия
- Параллельная версия с попыткой распараллелить внешний цикл
- Использована `#pragma omp critical` для защиты критической секции вставки
- Массив из 10 000 элементов
- Измерено время — ускорение ограничено из-за зависимостей данных

**Как работает:**
#pragma omp parallel for schedule(dynamic)
for (int i = 1; i < n; ++i) {
int key = arr[i];
int j = i - 1;
#pragma omp critical
{
while (j >= 0 && arr[j] > key) {
arr[j+1] = arr[j];
j--;
}
arr[j+1] = key;
}
}
