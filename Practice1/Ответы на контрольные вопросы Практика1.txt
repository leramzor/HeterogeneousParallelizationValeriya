В чём основные отличия между массивами и динамическими структурами данных?
Массивы — статические структуры с фиксированным размером, элементы хранятся последовательно в памяти, доступ по индексу O(1), но вставка/удаление в середине дорогая.
Динамические структуры (списки, стеки, очереди) — размер может меняться во время выполнения, используют указатели и динамическую память, удобны для частых вставок/удалений, но требуют дополнительной памяти на указатели и имеют более медленный доступ по индексу.
Что такое указатель, и как он используется в языке C++?
Указатель — переменная, хранящая адрес другой переменной или объекта в памяти.
Используется для: прямого управления памятью (new/delete), создания динамических структур данных (списков, деревьев), передачи больших объектов в функции по ссылке, работы с массивами.
Объясните принцип работы стека и очереди.
Стек — LIFO (Last In, First Out): последний добавленный элемент удаляется первым. Операции: push (добавить на вершину), pop (удалить с вершины).
Очередь — FIFO (First In, First Out): первый добавленный элемент удаляется первым. Операции: enqueue (добавить в конец), dequeue (удалить из начала).
Каковы преимущества и недостатки односвязных списков по сравнению с массивами?Преимущества: динамический размер, эффективные вставка/удаление в известной позиции (O(1)), нет переаллокации.
Недостатки: дополнительная память на указатели, медленный доступ по индексу (O(n)), плохая локальность кэша (хуже производительность при обходе).
Как правильно освобождать память в языке C++ после работы с динамическими структурами?
Для одиночного объекта: delete ptr;.
Для массива: delete[] arr;.
В деструкторах классов освобождать все выделенные узлы. Использовать RAII (например, smart pointers: unique_ptr, shared_ptr) для автоматического освобождения.
Почему важно понимать работу с указателями и динамической памятью для параллельного программирования?
В параллельных программах (особенно гетерогенных — CPU+GPU) данные часто передаются между устройствами, выделяются большие массивы в динамической памяти. Неправильное управление памятью приводит к утечкам, гонкам данных, ошибкам сегментации. Понимание указателей необходимо для корректной передачи данных в OpenMP, CUDA и другие фреймворки.
Как использовать reduction в OpenMP для нахождения суммы, минимума или максимума в массиве?
Используется директива #pragma omp parallel for reduction(оператор:переменная).
Примеры:
Сумма: reduction(+:sum)
Минимум: reduction(min:min_val)
Максимум: reduction(max:max_val)
OpenMP создаёт локальную копию переменной для каждого потока, выполняет операцию локально, затем объединяет результаты.

Как влияет параллельное программирование на производительность при работе с большими массивами?
На больших массивах (миллионы элементов) параллельное выполнение (с помощью OpenMP) значительно ускоряет операции (суммирование, поиск min/max), так как работа распределяется по нескольким ядрам CPU. Ускорение приближается к числу ядер (по закону Амдала). Эффект особенно заметен на массово-параллельных задачах, как показано в лекции (параллельное суммирование массива).
