Краткое описание решения и результатов
Задание 1 — Глобальная редукция (Сумма массива)
Реализовано суммирование элементов массива с использованием атомарных операций (atomicAdd).

Теория (Лекция №5, 7): Чтобы избежать "состояния гонки" (Race Condition), когда несколько потоков одновременно пишут в одну ячейку памяти, используются атомарные функции, которые блокируют доступ к адресу на время записи.

Задание 2 — Префиксная сумма (Hillis-Steele Scan)
Реализован алгоритм сканирования массива с использованием Shared Memory.

Теория (Лекция №4, 7): Данные сначала загружаются в сверхбыструю разделяемую память блока. Синхронизация потоков обеспечивается барьером __syncthreads(), что критично для корректности алгоритма Hillis-Steele.

Задание 3 — Гибридное умножение (OpenMP + CUDA)
Задача распределена между процессором и видеокартой:

CPU (OpenMP): Обрабатывает первую половину массива (Лекция №2, 8).

GPU (CUDA): Обрабатывает вторую половину массива (Лекция №3).

Вывод: Показано, как комбинировать ресурсы системы для достижения максимальной производительности.

Задание 4 — Распределенное суммирование (MPI)
Реализовано вычисление суммы на нескольких независимых процессах.

Теория (Лекция №9, 10): Использование функции MPI_Reduce для сбора локальных сумм со всех процессов в общую глобальную сумму на мастер-процессе (Rank 0).

Контрольные вопросы
1. В чём заключается отличие гибридных вычислений от вычислений только на CPU или только на GPU?
Гибридные вычисления используют сильные стороны обеих архитектур одновременно. CPU (OpenMP) лучше справляется со сложной логикой и последовательными частями кода, а GPU (CUDA) берет на себя массивные математические вычисления. Это позволяет избежать простоя ресурсов системы.

2. Для каких типов задач целесообразно распределять вычисления между CPU и GPU?
Для крупномасштабных задач, которые включают в себя как тяжелую математику (GPU), так и сложную предварительную или последующую обработку данных (CPU). Например, в задачах видеоаналитики: CPU декодирует поток, а GPU накладывает фильтры или распознает объекты.

3. В чём разница между синхронной и асинхронной передачей данных между CPU и GPU?
Синхронная передача (cudaMemcpy) блокирует выполнение программы на CPU до тех пор, пока данные не будут полностью скопированы. Асинхронная передача (через потоки/streams) позволяет CPU продолжать работу или запускать другие ядра GPU прямо во время копирования данных.

4. Почему асинхронная передача данных может повысить производительность программы?
Она позволяет реализовать перекрытие (overlapping) вычислений и передачи данных. Пока одна часть данных копируется на GPU, другая часть уже может обрабатываться ядром, что минимизирует общие временные затраты (Лекция №10).

5. Какие основные функции MPI используются для распределения и сбора данных между процессами?
MPI_Scatter: распределение частей одного массива от мастера ко всем процессам.

MPI_Gather: сбор частей обратно к мастеру.

MPI_Reduce: сбор данных с одновременным выполнением операции (сумма, максимум и т.д.).

MPI_Bcast: рассылка одного значения всем процессам.

6. Как количество процессов MPI влияет на время выполнения программы и почему?
В идеале увеличение числа процессов уменьшает время выполнения (закон ускорения). Однако, согласно Закону Амдала, ускорение ограничено последовательной частью кода и накладными расходами на пересылку сообщений между процессами по сети.

7. Какие факторы ограничивают масштабируемость распределённых параллельных программ?
Высокие задержки сети при передаче данных.

Неравномерная загрузка узлов (Load Imbalance).

Синхронизационные барьеры (ожидание самого медленного процесса).

8. В каких случаях использование распределённых вычислений оправдано, а в каких — неэффективно?
Оправдано: когда данные не помещаются в память одного компьютера (Big Data) или когда объем вычислений требует недель работы на одной машине. Неэффективно: для маленьких задач, где время на запуск процессов и пересылку данных по сети превышает время самого расчета.
