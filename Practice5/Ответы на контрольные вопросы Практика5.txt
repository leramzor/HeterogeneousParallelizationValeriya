Контрольные вопросы практической работы №5

В чём отличие стека и очереди?
Стек (Stack, LIFO — Last In, First Out) — структура данных, в которой элементы добавляются и удаляются только с одного конца (вершины). Последний добавленный элемент будет первым удалённым (принцип «последний вошёл — первый вышел»).
Очередь (Queue, FIFO — First In, First Out) — структура данных, в которой элементы добавляются в конец (enqueue), а удаляются из начала (dequeue). Первый добавленный элемент будет первым удалённым (принцип «первый вошёл — первый вышел»).
Различия в применении (Лекция №5): стек используется для рекурсии, отмены действий (undo), парсинга выражений; очередь — для буферизации задач, планировщика задач, обработки потоков данных.
Какие проблемы возникают при параллельном доступе к данным?
При параллельном доступе к общим данным (особенно в GPU, где тысячи потоков работают одновременно) возникают следующие основные проблемы (Лекция №5 + Лекция №3 + Лекция №4):
Гонки данных (race conditions) — когда несколько потоков одновременно читают и изменяют одну и ту же ячейку памяти, результат становится непредсказуемым.
Конфликты доступа к памяти — особенно в глобальной памяти, где атомарные операции могут привести к высокой конкуренции (contention).
Некоалесцированный доступ — когда потоки читают/пишут в разнесённые адреса, что сильно замедляет работу (Лекция №4).
Переполнение стека/очереди — в фиксированной памяти GPU легко выйти за пределы (Лекция №5).
Синхронизационные накладные расходы — частые __syncthreads() или атомарные операции замедляют выполнение (Лекция №4).

Как атомарные операции помогают избежать конфликтов в параллельных структурах данных?
Атомарные операции (atomicAdd, atomicSub, atomicCAS, atomicExch и др.) выполняются как неделимые (atomic) — за один цикл, без прерывания другими потоками (Лекция №3 + Лекция №5).
В стеке: atomicAdd(&top, 1) безопасно увеличивает указатель вершины и возвращает старое значение для записи (push).
В очереди: atomicAdd(&tail, 1) для enqueue, atomicAdd(&head, 1) для dequeue.
atomicCAS (Compare-And-Swap) позволяет реализовать lock-free операции (проверка и изменение в один шаг).
Это предотвращает гонки данных и обеспечивает безопасность при одновременном доступе тысяч потоков (Лекция №5: ключевая концепция параллельных структур на GPU).

Какие типы памяти CUDA используются для хранения данных?
CUDA предоставляет несколько типов памяти (Лекция №4 + Лекция №3):
Глобальная память (global) — самая большая (гигабайты), доступна всем потокам, медленная, используется для хранения основного массива/структуры (стек и очередь в нашей работе).
Разделяемая память (shared) — быстрая (внутри блока), небольшая (десятки КБ на блок), используется для временных данных и обмена внутри блока (Лекция №4: оптимизация).
Локальная память (local) — очень быстрая (регистры), ограничена (десятки байт на поток), используется для локальных переменных в ядрах (Лекция №4: временные данные).
Константная память (constant) — только чтение, кэшируется, для неизменяемых параметров.
Текстурная память — для оптимизированного чтения 2D/3D данных (не используется в работе).

Как синхронизация потоков влияет на производительность?
Синхронизация (__syncthreads() внутри блока, cudaDeviceSynchronize() на хосте) необходима для корректности, но сильно замедляет выполнение (Лекция №3 + Лекция №4):
__syncthreads() останавливает все потоки блока до завершения предыдущих операций — создаёт барьер (Лекция №4: высокие накладные расходы).
Частые синхронизации → низкая производительность (потоки простаивают).
Редкие синхронизации → высокая скорость, но риск ошибок (гонки данных).
Оптимизация (Лекция №4): минимизировать количество __syncthreads(), использовать атомарные операции вместо синхронизации, проектировать алгоритмы с минимальной зависимостью между потоками.

Почему разделяемая память важна для оптимизации работы параллельных структур данных?
Разделяемая память (shared) — самая быстрая память на GPU после регистров (Лекция №4):
Доступ в десятки раз быстрее глобальной памяти (низкая латентность).
Общая для всех потоков одного блока — идеальна для обмена данными и временных результатов внутри блока.
Позволяет минимизировать глобальные доступы — главную причину замедления (Лекция №4: минимизация глобальной памяти).
В параллельных структурах (стек/очередь) shared используется для буферизации, локальной обработки, слияния подмассивов, что значительно ускоряет работу (Лекция №5: ключевая оптимизация для структур данных на GPU).
