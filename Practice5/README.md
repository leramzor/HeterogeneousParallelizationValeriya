## Описание задания

**Цель работы:**
1. Освоить программирование параллельных структур данных с использованием CUDA.
2. Реализовать параллельные структуры данных: **параллельный стек (LIFO)** и **параллельная очередь (FIFO)**.
3. Провести исследование производительности реализованных структур данных (замеры времени на 1 000 000 операций).

Работа основана на материалах лекций:
- Лекция №1: Введение в гетерогенную параллелизацию
- Лекция №3: Архитектура GPU и программирование на CUDA
- Лекция №4: Типы памяти и оптимизация производительности на GPU

## Ключевые концепции

- **Параллельные структуры данных** — поддерживают безопасный одновременный доступ тысячами потоков (Лекция №5).
- **Атомарные операции** (`atomicAdd`, `atomicSub`) — обеспечивают безопасность push/pop/enqueue/dequeue без блокировок (Лекция №5).
- **Глобальная память** — используется для хранения стека/очереди (Лекция №4).
- **Атомарные операции** — предотвращают гонки данных при высокой конкуренции (Лекция №3 + №5).

## Краткое описание решения

### Задание 1 — Параллельный стек (LIFO) — part1_parallel_stack.cu

- Реализован стек в глобальной памяти с атомарным указателем `top`.
- **parallel_push** — атомарно увеличивает `top` и записывает значение.
- **parallel_pop** — атомарно уменьшает `top` и извлекает значение.
- **Вывод**: Атомарные операции обеспечивают безопасность при одновременной работе тысяч потоков (Лекция №5).

### Задание 2 — Параллельная очередь (FIFO) — part2_parallel_queue.cu

- Реализована очередь в глобальной памяти с атомарными указателями `head` и `tail`.
- **parallel_enqueue** — атомарно увеличивает `tail` и записывает в конец.
- **parallel_dequeue** — атомарно увеличивает `head` и извлекает из начала.
- **Вывод**: Атомарные операции гарантируют корректную работу в условиях высокой параллельности (Лекция №5).

## Выводы

- Параллельные стеки и очереди на GPU позволяют безопасно обрабатывать миллионы операций за доли секунды.
- Атомарные операции — ключевой механизм обеспечения корректности при высокой конкуренции (Лекция №5).
- Глобальная память подходит для больших структур, но требует атомарных операций для безопасности (Лекция №4).
- Ускорение по сравнению с последовательной реализацией на CPU достигает 10–50× (Лекция №5).
